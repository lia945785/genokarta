# Генокарта

Клієнтська частина програмної системи оцінювання генетичного ризику полігенних захворювань.
STEM-проєкт з дисципліни «Розробка фронтенду», частина курсової роботи.

Користувач завантажує файл ДНК-тесту, обирає хвороби, заповнює коротку анкету про спосіб життя
й отримує звіт. Звіт містить генетичну схильність (перцентиль), повноту розрахунку, внесок
маркерів і матрицю «гени × спосіб життя» зі сценарієм «що, якщо».

> Зараз це **фронтенд із заглушкою**: файл справді перевіряється в браузері, але результати
> аналізу беруться з мокових даних. Коли бекенд курсової буде готовий, достатньо замінити одну
> функцію (див. «Як підключити справжній бекенд»).

## Запуск

Потрібен [Node.js](https://nodejs.org/) версії 20 або новішої.

```bash
npm install        # встановити залежності (один раз)
npm run dev        # запустити в режимі розробки, адреса з'явиться в терміналі
npm test           # запустити модульні тести
npm run build      # перевірити типи й зібрати застосунок у папку dist
npm run preview    # переглянути зібрану версію
```

На сторінці завантаження є кнопка **«Скористатися демо-файлом»**. Вона підставляє
штучно згенерований файл `public/demo-genome.txt` у форматі 23andMe.

## Технології

- **React 19 + TypeScript**, збирання **Vite**.
- **Vitest** для модульних тестів.
- Кнопки — порт компонента `Button` з [Untitled UI React](https://www.untitledui.com/react/components/buttons)
  (ліцензія MIT) у `src/components/ui/Button.tsx`. API той самий (`color`, `size`,
  `iconLeading`, `iconTrailing`, `isLoading`, `isDisabled`), але стилі переписані на звичайний
  CSS, щоб не тягнути Tailwind і React Aria заради одного компонента. Якщо захочете оригінал,
  його можна додати через CLI `npx untitledui@latest add …` за
  [інструкцією](https://www.untitledui.com/react/docs/installation) (потрібен Tailwind v4):
  місця використання змінювати не доведеться.
- Решта (форми, вкладки, матриця, шкала перцентиля, спіраль ДНК на canvas) написана вручну,
  без бібліотек компонентів і маршрутизації, щоб кожну частину можна було пояснити на захисті.
- Шрифти Manrope (текст) і JetBrains Mono (цифри, rsID, гени, генотипи) встановлюються
  пакетами `@fontsource`, тому сторінка не звертається до сторонніх серверів.

## Дизайн

Темний «лабораторний» інтерфейс (Dark Bio-Genomics: Violet & Emerald). Усі кольори задані
змінними в `src/styles/global.css`.

| Роль | Колір |
| --- | --- |
| Тло застосунку | `#090B0E` |
| Панелі | `#11141A`, рамка `1px #1F2430`, без тіней |
| Текст / підписи | `#F1F5F9` / `#94A3B8` |
| Керування, вибір, покриття даних | фіолетовий `#8B5CF6` / `#A78BFA` |
| Сприятливо, низький ризик, лінії ДНК | зелений `#10B981` / `#34D399` |
| Середній рівень | бурштиновий `#F59E0B` |
| Несприятливий спосіб життя (те, що можна змінити) | кораловий `#F43F5E` |
| Висока генетична схильність (те, що змінити не можна) | приглушений рожевий: 60 % коралового + 40 % `#94A3B8` |

Заокруглення 4–6 px, без градієнтів і світіння. Шкали зроблені як приладні: темна підкладка,
суцільна заливка, засічки й візир. Матриця «гени × спосіб життя» — теплова карта з
напівпрозорих клітинок. Таблиця маркерів оформлена як консоль, генотипи — моноширинні бейджі з
підсвіченими ефектними алелями. Англійських технічних міток над блоками немає: заголовки
говорять мовою користувача. Під час друку кольори автоматично стають світлими.

## Як влаштовано оцінку

**Генетична складова** (у демо-версії береться з `mockReports.ts`):
- перцентиль 0–100 відносно референсної групи;
- зони: нижні 20 % — низька схильність, верхні 20 % — висока, решта — середня;
- внесок маркера = кількість ефектних алелів у генотипі × вага;
- повнота та обмеження: частка знайдених маркерів, частка покритої ваги скору,
  кількість виключених неоднозначних маркерів.

**Хвороби** (`data/diseases.ts`): ішемічна хвороба серця, інсульт, фібриляція передсердь,
артеріальна гіпертензія, діабет 2 типу, колоректальний рак, бронхіальна астма, хвороба
Альцгеймера. Для кожної в моках є реальні rsID і гени з GWAS (наприклад, PITX2 rs2200733 для
фібриляції передсердь, SMAD7 rs4939827 для колоректального раку, IL33 rs1342326 для астми).

**Спосіб життя** (рахується у браузері, `domain/lifestyle.ts`). Модель побудовано за
дослідженням [Khera A. V. et al., NEJM, 2016](https://pmc.ncbi.nlm.nih.gov/articles/PMC5338864).
Там використано чотири фактори: некуріння, ІМТ < 30, фізичну активність щонайменше раз на
тиждень і здорове харчування. Спосіб життя вважається сприятливим, якщо виконано 3–4 фактори,
проміжним — 2, несприятливим — 0–1. За високого генетичного ризику сприятливий спосіб життя
був пов'язаний із відносним ризиком коронарних подій на 46 % нижчим, ніж несприятливий.

Для ішемічної хвороби серця використано саме ці чотири фактори. Для інсульту ті самі чотири
фактори взято з дослідження [Rutten-Jacobs L. C. A. et al., BMJ, 2018](https://doi.org/10.1136/bmj.k4168)
(306 473 учасники UK Biobank): несприятливий спосіб життя був пов'язаний із ризиком інсульту
на 66 % вищим, ніж сприятливий, незалежно від генетичного ризику. Для інших хвороб набір
факторів (сон, алкоголь, середовище) **ілюстративний**, і застосунок прямо про це пише.
Правило категорій однакове: частка сприятливих факторів ≥ 75 % — сприятливий,
≥ 50 % — проміжний, інакше несприятливий. Харчування спрощено до 8 звичок; воно вважається
здоровим, якщо виконано хоча б 4.

Матриця показує лише відносний рівень ризику відтінком клітинки, без вигаданих відсотків.

## Як підключити справжній бекенд

Замініть тіло функції `requestAnalysis` у `src/api/analysis.ts` на запит до сервера.
Приклад є в коментарі в цьому ж файлі. Решта застосунку працює з типом `AnalysisReport`
і змін не потребує. Щоб передати сам файл, збережіть об'єкт `File` у `FileDropzone`
(зараз зберігаються лише назва, формат і кількість маркерів).

## Обмеження

- Результати аналізу демонстраційні й не обчислюються з файлу.
- Застосунок не є медичним виробом і не ставить діагноз.
- Перцентиль показує положення серед людей референсної групи, а не ймовірність захворіти.
